# zenmoney-mcp

MCP-сервер для read-only аналитики расходов из [ZenMoney](https://zenmoney.ru). Claude Code
запускает его по stdio в Docker-контейнере на каждую сессию, сервер держит локальную копию
данных в SQLite и отвечает на вопросы о тратах.

## Безопасность

- Только чтение. Сервер умеет единственный запрос к API — `POST /v8/diff/` с двумя метками
  времени. Тело запроса описано типом без полей под сущности, отправить изменение нельзя
  даже по ошибке.
- Сеть только до `https://api.zenmoney.ru`, редиректы не выполняются, телеметрии нет.
- Токен берётся из `ZENMONEY_TOKEN`, не логируется и не попадает в ответы тулов. Логи идут
  в stderr, stdout занят протоколом.
- Файл базы создаётся с правами `0600`. Контейнер работает от `nonroot` с read-only
  корневой ФС, без capabilities и без проброшенных портов.

## Тулы

Все помечены `readOnlyHint`. Даты в формате `YYYY-MM-DD`, суммы в валюте счёта, итоги
разбиты по валютам.

| Тул | Параметры | Что делает |
|---|---|---|
| `sync` | — | Принудительный синк: сколько сущностей обновлено и удалено, время синка |
| `list_accounts` | `include_archived` | Счета с балансами и валютами |
| `list_transactions` | `date_from`, `date_to`, `category`, `payee`, `min_amount`, `max_amount`, `type`, `limit` | Операции с названиями счетов и категорий; по умолчанию 30 дней до `date_to`, 100 штук, максимум 1000 |
| `spending_summary` | `date_from`, `date_to`, `group_by`, `category`, `limit` | Траты по `category` / `subcategory` / `merchant` / `day` / `week` / `month`: сумма, количество, доля; по умолчанию с 1-го числа месяца `date_to` |
| `compare_periods` | `a_from`, `a_to`, `b_from`, `b_to` | Сравнение двух периодов по категориям: разница и изменение в процентах |
| `recurring_payments` | `months`, `min_count` | Поиск подписок: один получатель, похожая сумма, ровный интервал |

Как считается:

- Расход — `outcome > 0` и `income = 0`, доход — наоборот. Если ненулевые обе суммы, это
  перевод между своими счетами (в том числе в долг). Он не входит ни в расходы, ни в доходы.
- Категория операции — первый тег. Категория верхнего уровня включает подкатегории, фильтр
  `category` ищет подстроку без учёта регистра.
- Фильтр `payee` ищет и в названии мерчанта, и в получателе из выписки.
- Подписки сортируются сначала по валюте (RUB первым), внутри — по стоимости в месяц.
- «Сегодня» считается в поясе `TZ`, по умолчанию `Europe/Moscow` (см. `.env.example`).
- Данные старше 10 минут синхронизируются перед ответом. Если синк не удался, но копия
  есть, тул отвечает по ней и предупреждает об этом первой строкой. После неудачи автосинк
  минуту не повторяется, чтобы недоступный API не тормозил каждый вызов; тул `sync` идёт
  в API всегда.

## Установка

Нужны Docker с плагином compose.

1. Получите токен на [zerro.app/token](https://zerro.app/token): войдите через ZenMoney
   и скопируйте токен со страницы.
2. Склонируйте репозиторий и создайте `.env`:

   ```bash
   cp .env.example .env
   # вписать токен в ZENMONEY_TOKEN
   ```

3. Соберите образ и проверьте токен:

   ```bash
   make docker-build
   make check   # OK: N счетов, M транзакций
   ```

   Первый `check` скачивает всю историю, следующие запуски берут только изменения.

## Подключение к Claude Code

Если Claude Code запущен на той же машине, что и Docker:

```bash
claude mcp add zenmoney -- docker compose -f /path/to/zenmoney-mcp/docker-compose.yml run --rm -T zenmoney-mcp
```

Если Claude Code на другой машине, а сервер на VPS, контейнер запускается через ssh:

```bash
claude mcp add zenmoney -- ssh my-vps docker compose -f /path/to/zenmoney-mcp/docker-compose.yml run --rm -T zenmoney-mcp
```

`-T` обязателен: без него compose выделяет TTY, и протокол ломается. Служебные сообщения
compose (создание контейнера) идут в stderr и протоколу не мешают.

Если токен протух, тулы отвечают ошибкой со ссылкой на zerro.app/token. Новый токен
вписывается в `.env`, пересобирать образ не нужно.

## Данные

База лежит в named volume `zenmoney-mcp_zenmoney-data`. Это кэш: при удалении
(`docker compose down -v`) следующий запуск скачает всё заново.

Несколько сессий Claude Code — это несколько контейнеров на одном файле. Поэтому база в режиме
WAL (чтение не ждёт чужую запись), а дифф старше уже записанного не применяется.

## Разработка

```bash
make build         # bin/zenmoney-mcp
make test          # go vet + go test
make lint          # golangci-lint v2, конфиг .golangci.yml
make docker-build
```

Без Docker сервер запускается так:
`ZENMONEY_TOKEN=... ZENMONEY_DB=./zm.db ./bin/zenmoney-mcp --check`.

Зависимости:

- официальный MCP SDK (`github.com/modelcontextprotocol/go-sdk`);
- GORM (`gorm.io/gorm`) с диалектом `github.com/glebarez/sqlite` на движке
  `modernc.org/sqlite`: чистый Go, cgo не нужен ни для сборки, ни для тестов;
- остальное — стандартная библиотека.

Схему создаёт `AutoMigrate` из моделей в `internal/store/models.go`. Отдельных миграций нет:
база — кэш, и при несовместимой смене схемы её проще удалить и синхронизировать заново.
